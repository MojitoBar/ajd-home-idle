# 화면 검수 지침 (6차 검수, 2026-11-15)

웹 방치형 게임 "우리 집 키우기"(도트 화풍, 일반 공개용)의 스크린샷을 한 장씩 원본 그대로 Read해서 **흠**을 찾는다. 사용자는 "아쉬운 점이 안 나올 때까지 고쳐라"고 했고 버튼 하나, 글자 하나까지 본다. 5차 검수에서 나온 흠을 모두 고친 뒤 전체 화면을 다시 찍었다 — 이번에는 **덜 고쳐진 것과 고치다가 새로 생긴 흠**을 찾는다. 코드나 화면은 고치지 않는다. 브라우저도 쓰지 않는다(이미지 Read만).

## 무엇이 흠인가
- 겹침·가림: 글자가 그림·다른 글자·테두리에 걸침, 칩이 글자를 덮음, 창이 화면 밖으로 나감.
- 잘림·넘침: 글자가 칸 밖으로 나가거나 잘림, 줄바꿈이 어색함(한 글자만 다음 줄 등).
- 정렬·간격: 같은 줄 요소의 높이가 어긋남, 여백이 좌우·위아래 다름, 버튼이 가장자리에 붙음, 큰 빈 곳, 같은 종류 요소의 크기가 화면마다 다름.
- 일관성: 같은 뜻인데 다른 낱말, 같은 역할 버튼인데 다른 색·크기, 창마다 다른 제목 모양.
- 읽기: 글자가 뭉개져 안 읽힘, 배경과 대비가 약함, 뜻이 통하지 않는 문구, 오타, 어색한 한국어.
- 화풍 위반(아래 규칙), "AI가 만든 티"가 나는 장식(뜻 없는 칩·선·그림자 남발).
- 연출 잔재: 사라져야 할 입자·번쩍·말풍선이 남아 있음. 반대로 연출이 뚝 끊기거나 밋밋해 보이는 것도 흠(사용자는 이펙트를 가장 중시한다).

## 화풍·UI 규칙(어기면 흠)
- 도트: 1도트 = 2 CSS px, 둥근 모서리·그라데이션·흐림·번짐 그림자·반투명으로 상태 표현·이모지·회전·곡선 금지.
- 팔레트 24색: 남색 계열(#0d1430, #16224a, #3b4a7a, #8a96b8, #d6dcec, #ffffff), 크림(#fff3d6, #ecd3a0), 나무(#8a4f24, #d08a4a), 파랑(#0b3aa0, #145ce6, #5b9bff, #bcd6ff), 노랑(#7a4a00, #c98a00, #ffc83d, #ffeaa0), 빨강(#a8142d, #e9304b), 주황 #ff8a1f, 초록 #2fb36b, 보라 #8d5cf6, 분홍 #ff6fb0.
- 글자 크기는 12·15·24·30·36·48px만(PC 방 2배 화면의 방 안 글자는 그 2배).
- 버튼: 주 = 파랑 면 + 흰 글자, 보상 받기 = 노랑 면 + 남색 글자, 보조 = 크림 면 + 남색 글자 + 남색 선, 위험 = 빨강 면 + 흰 글자. 빨강은 약정·위험·남은 시간·`탭` 칩에만. 알림 점·피버·"열림" 강조는 주황. "새로 얻음"은 노랑.
- 창 제목: 24px 남색 글자 + 아래 남색 2px 선. 보상 창은 제목 왼쪽에 노랑 `보상`/`특전` 칩, 일반 창은 제목 왼쪽에 아이콘.
- 토스트: 방 윗변 안쪽의 글자 폭 칩. 일반 = 남색 면 + 흰 글자, 보상 = 노랑 면 + 남색 글자, 열림 = 남색 면 + 주황 테두리. 최대 2개.
- 방 안 큰 글자(배너: `피버!`·`방 완성!`·`통신 결합 x1.5!`·`사은품 상자 도착!`): 토스트 아래·방 테두리 안쪽, 노랑 글자 + 남색 외곽선(`피버!`만 주황 판 + 남색 글자), 부제는 남색 면 + 흰 글자 칩. 겹침 순서는 토스트 > 탭 숫자 > 배너. 단, 면이 있는 `피버!` 주황 판만 탭 숫자보다 위(숫자가 판 뒤에서 나와 떠오름).
- 방에서 나온 입자는 방 사각형 안에서만 보인다(보상 코인이 아래 포인트 표시로 날아가는 것만 예외).
- 방 아래 막대: 상자 단계는 상자 색(갈색)으로 **남은 내구도**(새 상자 = 가득), 손질 단계는 파랑으로 진행도.

## 흠이 아닌 것(의도·결정 — 적지 않는다)
- 집 5곳의 살림 그림이 같음(배경만 바뀜). 모달에 ✕ 버튼 없음. 새 게임의 자물쇠 탭 칸.
- 타격 순간 상자가 한 프레임 흰색이 됨. 서비스 카드의 구매·약정 버튼 2단.
- 새 게임 첫 화면(`*-01-main-early`, `n00-new-start`)의 안내 말풍선. 새 게임에서 PC 오른쪽 단 아래가 비는 것.
- 집 이름이 길어 자리가 모자랄 때 머리의 집 아이콘이 숨음. 높이 760 이하 모바일(360 폭 사진)에서 머리 부제 `기본 회선`이 숨음.
- 이사 진행 칩 문구가 폭에 따라 `이사 목표 N% · 금액 P` / `이사 목표 N%` / `이사 N%`로 줄어듦. 방 아래 막대 줄에서 자리가 모자라면 `· 냉장고`·`탭 +N` 글자가 빠짐.
- 토스트가 떠 있는 동안 방 윗부분(선반 그림)을 가림. PC 방 2배에서 토스트 글자가 30px. 떠오르는 탭 숫자가 선반 위를 지나감.
- 방 1배 PC 화면·1920 폭에서 왼쪽 단 아래가 비는 것(방은 정수 배율만). PC에서 창(모달)이 1배 크기.
- PC 방 2배 화면 가운데 높이 940 미만(1440×900 등)에서는 방 아래 이사 줄(이사 목표 칩·`집 단계`·`이사` 버튼)이 1배 크기(세로 공간 부족).
- PC(900 이상) 도감 칸에 `미발견` 글자 없음. 빈 살림 자리 점선 칸에 이름표 없음. 밤 집 배경의 별 점.
- 굵은 글꼴(24px 이상 제목)에서 `특`·`통`·`투`가 `득`·`동`·`두`처럼 보임(글꼴 특성). `특전` 칩만 보통 굵기.
- 황금 `우주 정수기` 그림이 물통 얹은 정수기 모양. 퀴즈 보기 카드 순서가 매번 섞임.
- PC 오른쪽 단 안의 8px 도트 스크롤바.
- 디버그용 토스트의 `?` 아이콘(촬영용 가짜 이름).
- 확률 숫자·가격 숫자의 균형(이번 검수는 화면만 본다).
- 430 폭에서 방이 아래 카드보다 좌우 34px 안쪽(방은 정수 배율만). 360 등 낮은 화면에서 목록이 스크롤로 잘려 보임.
- 신화 결과 창 테두리 색이 사진마다 다름(색 순환 연출). 신화 번쩍의 전체 흰 프레임. Lv 192 반짝이 깜박임.
- 방 아래 막대 줄의 `탭 +N` 파란 글자. 결과 창 밖에 남은 색종이 한두 점. 연출 중간 프레임(등장·퇴장 도중)의 어긋난 모양.
- 모바일 이사 완료 화면(내용 묶음이 세로 가운데 — 위아래 큰 여백은 의도). `>>` 옆 점은 색종이 입자.
- 10개 결과 화면: 제목·카드·요약·버튼이 한 묶음으로 세로 가운데(위아래 여백이 같음), 입자가 카드 위로 지나감.
- 확률 창은 화면을 거의 다 덮어 뒤 화면의 어두운 부분이 위쪽 조금만 보임.
- 피버 시작 순간 0.4초 동안 화면 전체가 2~4px 흔들림(연출). 피버 중 집 이름이 주황↔노랑으로 깜박임(남색 외곽선).
- 상담 요청 칩이 주황↔노랑으로 깜박임. 사은품 상자 장면에 들어갈 때 남색 면이 3프레임으로 걷히는 전환.
- 구매할 때 떠오르는 `+N/초` 글자가 카드 안 생산량 줄 옆에서 12px만 떠오름. 구매 반짝이가 서비스 목록 윗변에서 사라짐.
- 900~1079 폭 PC 도감은 한 열. 모바일 도감 등급 칩은 3+2 두 줄.
- 방 아래 피버 막대·상자 막대 줄·이사 줄의 좌우 끝은 방 바깥선과 같다. 그래서 390 폭에서 `결합` 줄·서비스 카드가 방보다 좌우 1px 넓고, 360 폭에서 `결합` 칸 오른쪽 끝이 `이사` 버튼보다 2px 안쪽이며, 430 폭에서 방과 방 아래 줄이 카드보다 좌우 34px 안쪽이다.
- 360×740에서 집 단계 창 안이 스크롤됨.
- 이사 장면의 큰 글자 `출발`의 획 뭉침(글꼴 특성).
- PC 도감에서 토스터 그림이 칸에 꽉 참.
- 손질 단계에서 손질 중인 살림에 윤곽선이 보임(손질 표시).
- 숫자가 올라가는 도중 프레임의 옅은 글자.
- 밤 집(펜트하우스)·은하 분양단지의 벽 전화기는 아래 줄이 없는 짧은 모양. 우주 끝 신도시의 창은 벽 기둥으로 둘로 나뉘고 전화기가 그 기둥에 걸림.
- 조리대 위 빈 살림 자리 점선 칸은 바닥 살림 칸보다 여백이 좁음(1도트).
- `이사 목표 달성!` 순간 `이사` 버튼 주변에만 반짝이가 터짐.
- 구매 순간 `+N/초` 글자는 남색 칩 + 노랑 글자. 건너뛰기 안내는 상자 장면·이사 장면 모두 `누르면 건너뛰어요`.
- PC 10개 결과의 입자는 모바일의 2배 크기.
- PC 10개 결과에서 터지는 첫 순간(100ms) 큰 입자가 `신규` 칩 위를 지나감(0.3초 뒤에는 안 가림).
- 부재 보상 창 본문 둘째 줄이 첫 줄보다 옅은 색(보조 문구). 이사 도착 직후 집 윤곽 사이로 비치는 반짝이 1~2점. 떠오르는 탭 글자끼리 겹치는 중간 프레임.
- 구매 `+N/초` 칩이 360 폭·긴 숫자에서 생산량 글자 끝을 덮음(이름·`Lv` 칩은 안 덮음). 구매 때 날아가는 아이콘이 방 아래 줄 글자 위를 지나감.
- `이사 목표 달성!` 순간 `이사` 버튼이 노랑으로 번쩍이고 테두리에서 반짝이가 나옴(연출).

## 방법
- 무엇을 찍은 사진인지는 `screenshots/audit6/INDEX.md`에서 해당 파일 줄만 grep해서 확인한다(통독하지 않는다).
- 맡은 사진을 **빠짐없이 한 장씩** Read한다. 축소해서 대충 보지 않는다. 같은 사진을 두 번 읽지 않는다.
- 추측으로 흠을 만들지 않는다. 사진에서 실제로 보이는 것만 적는다. 확신이 약하면 `(불확실)`을 붙인다. 흠이 없으면 "흠 없음"이라고 적는다. 억지로 채우지 않는다.
- 같은 흠이 여러 사진에 나오면 한 줄로 묶고 파일 이름을 나열한다.
- 파일을 만들지 않는다. 다른 에이전트를 띄우지 않는다. 컨텍스트가 120k를 넘을 것 같으면 그때까지 본 것을 보고하고, 못 본 파일 이름을 적고 끝낸다.

## 보고 형식(한국어, 본문으로 반환, 60줄 이하)
1. 본 장수 / 맡은 장수, 못 본 파일.
2. 흠 목록(심각한 것부터): `[상|중|하] 파일 이름(들) — 화면의 어디 — 무엇이 어떻게 문제인지 — 고칠 방향 한 구절`
   - 상 = 누가 봐도 깨져 보임(겹침·잘림·안 읽힘·오타), 중 = 어색함(정렬·간격·일관성), 하 = 취향에 가까운 다듬기.
3. 좋아 보여서 건드리지 말아야 할 것 3개 이하.
