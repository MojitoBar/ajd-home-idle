# 상자 풀기 현재 동작 (2026-11-15 촬영, 수정 전)
촬영: `tools/shots-unpack.cjs`, 390x844 DPR1, CDP `Page.startScreencast`(png)로 받은 프레임을 타임스탬프 격자에 맞춰 골랐다.
간격은 hit/break/after/dock 50~60ms, place·done은 길어서 100ms. 0ms = 마우스 down 시각이고 첫 화면 반응은 +100~150ms에 보인다(스크린캐스트 지연 포함, 게임 지연으로 단정 못 함).
스트립: hit/break/place/done/after/dock.png (dock = 하단 가운데 도구 버튼으로 친 것, 방 탭과 같은 `doTap`).

## 1. 탭 한 번의 순서
1. 입력: `.phone` 버튼이 방 전체의 투명 판(`m8-unpack.css:11`). `pointerdown` -> `doTap` (`app.ts:235`, `app.ts:531`). 독 버튼도 같은 `doTap` (`app.ts:247`).
2. 입력 제한: `tapGate` 초당 12회 초과면 무시, 6회 초과분은 감쇠(피해 0, 포인트 절반) (`economy.ts:276`, `services.ts:30-32`).
3. 로직: `tapAndHit` -> `tapWithRng`(포인트·치명타 난수 1회) -> `hitBox` (`unpack.ts:112`, `unpack.ts:70`).
   피해 = 탭 힘 x(치명타 배율) x 피버 배율. 치명타가 아니면 한 탭 피해 상한 = 상자 내구도의 1/3(`NONCRIT_CAP`) -> 일반 탭은 최소 3번.
4. 화면(안 터질 때): `unpackHit` (`unpackUi.ts:375`) -> `squash` 흰색 번쩍+눌림 3단계 x 83ms = 249ms (`:401`), `swing` 도구 휘두름 249ms (`:413`), `chips` 골판지 조각 7개(치명타 10, 피버 8, 감쇠 3) (`:454`), 치명타면 `fx.shake` 250ms + 별. 탭 숫자 `+56.1`은 `tapFx`가 띄움.
5. 상자 그림: `syncUnpack` (`:323`)에서 `stageOf` (`:27`)로 내구도 3등분(작은·보통 3장, 큰 상자 4장). 단계가 바뀌는 탭에서만 200ms 좌우 2px 흔들림. 그 사이 탭은 그림이 그대로(hit.png: 4/28 피해에 그림 변화 없음).

## 2. 보이는 상자와 남은 상자
- 방에는 항상 3개: 가운데(pos 0, 칠 대상) + 양옆 대기 2개 (`rebuild` `:149`, `layoutWait` `:137`). 막대 글자는 `상자 (열린 수+1)/80`.
- 실제 남은 상자 = 80 - `state.unpack.box`. 화면의 3개는 box, box+1, box+2번째이므로 남은 수가 3 미만이어도 80번 뒤 덤 상자가 대기 칸을 채운다(`boxKind`: 80번째부터 작은 상자만).
- 터지면: 로직이 이미 `box+1`이라 대기 상자가 즉시 앞으로(`setBoxPos`), 새 대기 상자가 `enter`(8px 아래에서 0.25s `steps(2)`, `m8-unpack.css:24`)로 오른쪽 뒤에 추가 (`boom` `:500-512`). break.png: +100ms에 흰 덩어리, +150ms에 옆 상자가 이미 가운데 자리.
- 터진 자리에 대한 연출: 가운데 상자 80ms 흰색 고정 후 제거, 뚜껑 조각 `lids` + 먼지 `fluff` (`:558-563`). 내용물이 120ms 뒤 60px 튀고(250ms) 날아간다.
- 큰 상자가 가운데로 올 때만 `dropIn`: 190px 위에서 250ms `steps(5)` 낙하(delay 200ms) + 450ms에 화면 흔들림 (`:490`).

## 3. 살림이 놓이는 조건과 연출
- 10개 묶음: 작은 x2, 보통, 작은 x2, 보통, 작은 x2, 보통, 큰 상자 (`BOX_PATTERN`). 큰 상자가 터질 때만 살림 1점(10번째마다, 총 8점: 냉장고~커피머신, `data/unpack.ts:46`). 보통·작은 상자는 해당 칸을 아래부터 10%씩 채울 뿐 (`slotFill`, `applySlots` `:293`).
- 큰 상자 연출(place.png): 터짐 -> 살림 그림이 상자 자리에서 120ms 뒤 60px 튀고 -> 300ms 대기 + 컨페티 16개 -> 700ms 포물선으로 칸까지 날아감 (`:580-606`). 날아가는 동안 칸은 숨김, 도착(약 +1400ms)에 12px 통통 튀며 먼지·반짝이(`release` `:526`). 토스트 `냉장고를 놓았어요`.
- 칸은 이미 90%까지 차 있다가 날아온 그림이 도착해야 100%가 된다(place.png -100ms: 왼쪽 냉장고가 보이는 상태에서 +100ms에 숨고 +1400ms에 다시 나타남).

## 4. 방 완성(80/80) 이후
- 80번째(k=79)는 큰 상자(커피머신). `hitBox`가 `roomDone=true`와 무료 사은품 상자(`grantFreeBox`)를 준다 (`unpack.ts:84-96`).
- 화면(done.png): 일반 큰 상자 연출 + `roomDone` (`:614`) 800ms 뒤 `glint` 깜빡 500ms·컨페티 30·`fx.rain(20)`, 1000ms 토스트 `정리 끝. 사은품 상자를 받았어요`, 3000ms에 사은품 연출 `playFree`. 막대 글자는 `덤 상자` + `방 완성` 칩으로 바뀜.
- 그 뒤 탭(after.png): 방에는 계속 작은 상자가 3개 나오고, 가운데 상자를 똑같이 친다. 탭당 포인트(+56.1)·피버 게이지(2%->6%)·콤보(`3연타`,`4연타`)·치명타 모두 그대로 동작한다(난수 판정 동일). 상자가 터지면 포인트 덩어리(`k=2`)만 나오고 살림·`item`·`slot`은 없다(`unpack.ts:92-104`). 새 살림·진행 목표는 없다.
- 이사: `prestige.ts:64`가 `unpack: initialUnpack()` = `{box:0, damage:0, roomDone:false}`로 되돌림. 상자 0/80, 살림 칸 비어 있음, 도구는 `tapLevel` 초기화로 맨손.

## 5. 스트립에서 눈에 띄는 점(사실 묘사)
- 안 터지는 타격(hit.png)은 상자 그림이 0~600ms 내내 같고, 변하는 것은 흰 번쩍(약 +100~350ms)·장갑·조각·숫자뿐. 3타 이상 쳐야 터지는데 단계 흔들림 외에 내구도 표시는 그림 단계 3장이 전부.
- 터짐(break.png)에서 흰 덩어리 한 프레임 뒤 상자 3개가 바로 옆 칸에서 재배치되고, 새 대기 상자는 같은 크기·같은 그림으로 오른쪽에 나타남. 터진 상자에서 나온 물건(TV)은 중앙 위로 튀어 오른 뒤 왼쪽 칸으로 감.
- 터짐 숫자 `+168 P`가 약 1000ms 창문 위에 머묾(+100~+700 프레임), 탭 숫자 `+56.1`과 겹쳐 보임.
- 탭 때마다 `+56.1`이 상자 우측 위에 쌓여 after.png 420ms 프레임에서 두 줄이 겹침.
- 큰 상자 터짐(place.png)은 살림이 칸에 닿기까지 약 1.3초 걸리는데 그 사이 다음 상자를 계속 칠 수 있고, 칸은 숨겨진 상태.
- 방 완성 뒤(after.png)에는 상자가 계속 같은 모양으로 나오고, 막대·살림·방에 변화가 없으며 `덤 상자` 표시만 바뀜.
- 촬영 한계: 스크린캐스트 프레임 간 시각 오차는 수십 ms, 막대 채움 변화는 육안으로 구분되지 않아 판단하지 않음.
